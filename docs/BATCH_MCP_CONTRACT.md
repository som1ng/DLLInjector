# 批量项目 MCP 配置契约

`setup --integration mcp --agent all --scope project` 显式配置 Codex、Claude Code、OpenCode。
用 `--codex-client`、`--claude-client`、`--opencode-client` 分别提供三个可信原生 EXE 的绝对路径；
共用 `--cli`、`--server`、`--allow-root`、可选 `--manifest` 与 `--allow-processes`。
不自动选择候选路径，不接受单一 `--client` 或 `--select`，三个客户端都必须提供。

## 配置与预检

- 仅项目级 setup，沿用已验证的客户端版本和配置格式。
  三个目标分别为 `.codex/config.toml`、`.mcp.json`、`opencode.json` 或 `.jsonc`。
- 写入前先预览全部目标，检查路径、配置/收据及可选分发清单。
  `--dry-run` 返回三个配置与记录路径，不启动程序、不写入、不询问交互输入。
- 正式安装逐个复用单客户端的版本校验、MCP 握手和七工具检查；`--verify` 增加写入后校验。
  预览不证明客户端版本或握手兼容，正式检查失败时仍可能触发回滚。
- 相同安装返回 unchanged；新目标返回 installed。结果分别列出每个客户端，
  不把协议握手成功等同于宿主自动发现、项目信任批准或模型自主调用。

## 回滚与内容保留

- 失败目标由自己的事务回滚，批量入口逆序撤回之前成功新增的目标。
  先前已有且 unchanged 的安装保持不变；不为失败批量操作删除它们。
- 在内存中保存本次提交前后的配置字节及托管收据，不将整个原配置写入输出、日志或收据。
  原配置可能包含与本工具无关的凭据；安装记录仍只包含本工具运行参数、哈希和所有权信息。
- 回滚在锁内核对原始托管收据，拒绝删除其他操作后来替换的不同有效安装。
  当前配置仍与本次提交一致时恢复最初字节（包括不存在）；否则只移除本工具条目，
  保留后来新增的其他配置。被修改的托管字段或无法保留的 JSONC 注释会阻止自动删除。
- 回滚失败、目标状态无法确认，或提交后的锁清理失败留下收据时，返回
  `ROLLBACK_INCOMPLETE`，列出失败客户端和需检查的路径，不输出配置正文。
- 不保证跨文件/客户端原子可见性，不保证强制终止或断电恢复；空父目录可能保留。
  校验和卸载仍明确指定单个客户端，避免不明确的批量删除。

## 验收

覆盖三种配置、预览无执行/写入、三条客户端路径校验、重复安装、已有条目保留、
最后目标写入/验证失败后的完整恢复、原始字节恢复、后来无关字段保留、
并发有效安装保护、锁清理异常，以及输出和收据不包含原配置私有字段。
真实 CLI/MCP 协议检查与真实客户端配置加载验证分别报告，后者仅用隔离临时项目和本地模型 fixture。
