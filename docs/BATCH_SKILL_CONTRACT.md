# 批量 Skill 安装契约

`setup --agent all` 为显式批量选择，为 Codex、Claude Code 和 OpenCode 写入 Skill，
不根据本机是否安装客户端来静默增删目标，也不表示客户端已经发现 Skill。
支持 `--scope project|user`，沿用单客户端入口的 `--cli`、`--manifest`、`--dry-run` 与 `--verify`。

- Codex/OpenCode 共用 `.agents/skills/windows-dll-doctor`，只执行一次安装；
  Claude 使用 `.claude/skills/windows-dll-doctor`。输出列出两个目标及各自覆盖的客户端。
- 开始写入前对两个目标都执行现有预检，检查目录、链接、托管内容及可选分发清单。
  预览不启动 CLI、不创建目录、不要求交互输入。CLI 的运行版本及既有安装与本次绑定
  是否完全一致，仍由正式安装验证；预览成功不保证正式安装成功。
- 正式安装复用原有暂存、锁、校验和冲突保护。相同内容返回 unchanged；不同绑定、
  手动安装或用户修改不会被覆盖。Skill 内容或 CLI 绑定变化仍需先显式卸载再安装。
  收据版本号仅标识创建它的安装器；当格式、所有权、文件哈希及 CLI 绑定仍匹配时，
  只升级安装器不会触发冲突或重写旧收据。
- 后续目标失败时，其单目标事务自行回滚；批量入口再逆序撤回本次成功新增的目标。
  本来就存在且返回 unchanged 的目标保持不变。回滚不启动 CLI。
- 回滚时重新检查托管内容；用户并发修改、额外文件、链接或锁冲突会阻止删除，
  并在锁内比对提交时保存的收据，保护其他操作后来创建的不同有效安装。
  返回 `ROLLBACK_INCOMPLETE` 以及需检查的目标路径。不得为完成回滚而覆盖用户修改。
  若单目标在提交后的锁清理阶段失败，且新目标仍存在，也必须报告回滚不完整。
- 不保证跨目录原子可见性，也不保证断电/强制结束恢复。空的父目录可能保留。
  错误输出分别报告失败客户端、已完成目标和回滚结果，不将部分成功伪装为全量成功。

本阶段只提供 Skill setup 的 all 入口。verify/uninstall 继续明确指定客户端，
Codex/OpenCode 共用目录只需选其中一个；MCP 与 Pi 沿用各自入口。

验收覆盖两个 scope、Unicode/空格路径、共享目标去重、预览无执行/写入、重复安装、
用户原文件保留、后续目标预检/安装/校验失败、既有安装保留、回滚遇到并发修改，
以及实际命令行入口使用可信 CLI 的安装和只读诊断。
