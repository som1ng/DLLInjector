# Skill 客户端发现验证契约

本轮补充真实已安装客户端的本地发现检查，不发起模型会话、推理或诊断工具调用。
不将发现成功当作自然语言自动触发、回答正确性或完整客户端兼容性证明。

## 范围

- Codex：stdio app-server 的 `initialize` / `initialized` / `skills/list`。
  不使用 `thread/start` 或 `turn/start`；核对客户端返回的项目路径、名称、描述和启用状态。
- OpenCode：`debug skill --pure`，关闭自动更新/模型目录获取，使用临时数据库与配置目录；
  核对实际发现的项目 Skill 路径和元数据。
- Pi：调用已安装包的资源发现器（不创建 AgentSession），禁用扩展、MCP、主题和提示模板；
  核对项目 Skill 元数据及是否进入可供模型选择的 skills 提示清单。
- Claude Code：只有在能够不发起推理地验证时才记录发现通过；否则明确未验证，
  不为了得到“全绿”把帮助/版本号或手工解析 YAML 当作客户端发现。

## 可复现检查

1. 在临时 Git 项目中复制完整权威包；使用中文、空格路径，从项目子目录查询。
2. 必须匹配临时项目中 `SKILL.md` 的规范化路径，不能仅凭同名用户级 Skill 判定通过。
3. 在另一未安装 Skill 的临时项目查询，不能出现该项目的 Skill。
4. 缺失客户端、启动失败、接口错误、输出不合法、发现失败或超时返回非零，
   不降级成通过或静默跳过用户指定的客户端。
5. 不输出其他已安装 Skill 的内容、身份凭证或完整客户端启动日志；摘要只包含
   所选客户端的版本、目标 Skill 检查结果和验证范围。
6. 不修改用户已有配置/Skill、不安装依赖；所有显式写入均在临时项目，完成后清理。
   客户端本身可能按其设计写运行日志/缓存，不能据此宣称进程没有任何外部副作用。

验证脚本是显式运行的维护工具，不放入默认 CTest，不要求每台构建机安装四种客户端。
现有命令示例回归仍由 `skill.contract` 负责。轻量单元检查可在 CI 中验证脚本自身的
路径/元数据判定，不能用替身结果代替上面的真实客户端记录。

以本机版本和实际响应为准；实验 API 的变动应报兼容性错误，不修改第三方客户端。
本轮若发现接入说明或包元数据不被客户端识别，只修正对应权威文件与文档。
